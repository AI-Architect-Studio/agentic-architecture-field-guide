# Support and change boundary

Agree support responsibility before a system becomes somebody's daily dependency. This editable scope schedule is operational planning, not a contract or an included support entitlement.

## Define what is supported

| Topic | Agreement to record |
| --- | --- |
| Supported version | [Release and configuration revisions] |
| Supported environment | [Runtime, deployment and dependency versions] |
| Supported use case | [Tenant, corpus, actions and workload envelope] |
| Included support | [Installation help, reproducible defects, documentation corrections] |
| Excluded work | [New integrations, custom features, extra tenants, provider migration, ongoing operations] |
| Intake route | [Existing private support channel and required evidence] |
| Response coverage | [Actual staffed hours and acknowledgement commitment, or none] |
| Maintenance period | [Start/end or renewal terms, with a named owner] |
| Emergency control | [Person able to disable the system] |

Do not promise continuous monitoring or a response time that nobody is responsible for meeting. A downloadable MIT pack provides source rights; it does not itself provide a hosted service or staffed support.

## Defect or new scope

A defect means the delivered version fails an agreed acceptance criterion in its supported environment. A new source, tenant, tool action, output format, model or operating environment is a change request until assessed.

Every report should include the expected behavior, observed behavior, exact versions, a minimal redacted reproduction, impact and a safe fallback. Exclude credentials and raw sensitive transcripts.

| Request | Effect on boundary | Evidence needed | Decision |
| --- | --- | --- | --- |
| [Description] | [Data / tool / model / operational / none] | [Compatibility and regression checks] | [Accept / scope / decline / hold] |

## Estimate the change

Separate implementation, validation, migration, documentation and support effort. Identify any provider charges and who authorizes them. Record an estimate as an estimate; a change order or quote becomes binding only through the parties' separate commercial process.

Reuse the prior evidence only where the affected scope remains unchanged. New model behavior needs new evaluation; a pricing or dependency change needs a refreshed cost/compatibility record. A new tenant needs an access-boundary test.

## End or transfer support

Name the final supported revision, export all permitted project artifacts, revoke the departing operator's grants through the real access system, and verify the receiving owner can run the fallback. Keep required records under the agreed retention policy. Mark inaccessible evidence and remaining risks; do not claim transfer completion from a document alone.
